# Technical debt backlog

1. `BACKLOG.md` — источник правды для отложенных технических замечаний.
2. После каждого архитектурного ревью добавлять новые замечания, если они не исправлены в текущем PR.
3. Не дублировать существующие записи.
4. Блокирующие замечания текущего этапа исправлять до PASS, а не переносить сюда ради ускорения merge.
5. Закрывать задачу только после проверки, ссылки на PR/SHA реализации и обновления статуса.
6. Наличие задачи здесь не разрешает Codex самостоятельно её реализовывать.
7. Изменение архитектуры или roadmap требует Architecture Change Gate.
