## Blockers
- OpenAI API key with billing needed for real-model smoke test; Fake model works without key.
- Only synthetic or authorized de-identified resumes permitted for demo.

Actionable deferred technical findings are tracked in [BACKLOG.md](BACKLOG.md).

## S00 risks / limits
- Test-client dependency warning: [BL-005](BACKLOG.md#bl-005).
- S00 checked only process startup, HTTP health, and UI availability states; it included no database, document, or LLM behavior.

## S01 risks / limits
- Startup `create_all` creates missing tables but does not migrate existing columns; explicit migrations remain a later design decision.
- Vacancy deletion is outside the documented S01 API. Criterion display order is a sortable integer; equal values use ID as a tie-breaker, and updates do not renumber peers.

## S02 risks / limits
- OCR and legacy `.doc` are unsupported. Oversized or storage-rejected files are returned per file but are not persisted because a complete content hash is unavailable.
- Multipart parser dependency: [BL-004](BACKLOG.md#bl-004). The batch limit is 20 files.
- Correcting a stored unsupported file reuses its opaque storage key when the bytes were already saved, even if the old key's suffix differs from the newly validated file type. No upload path is exposed by the API.

## S03 risks / limits
- The Fake provider uses conservative English/Russian phrase rules and exact criterion wording. It is an offline test/demo adapter, not a semantic evaluator.
- Citation checks verify source text, page, basic criterion relevance, and obvious weak or instruction-like quotes. They cannot prove every semantic claim; human review remains necessary. Possible false negatives for paraphrases: [BL-006](BACKLOG.md#bl-006).
- The sensitive-criterion filter targets explicit English/Russian wording; it cannot replace legal review or infer intent from ambiguous phrasing. Compound AND/И validation checks visible terms in the cited quote, not full semantic equivalence.
- No model is configured by default for OpenAI; model availability and account access were not tested. A real request would send the supplied text to OpenAI and requires explicit owner authorization and synthetic or authorized de-identified data.
- The S03 analysis service is reused by S04 for persisted batch execution; S03 itself did not expose analysis endpoints.

## S04 risks / limits
- The dispatcher exists only inside the FastAPI process. Shutdown or restart marks incomplete runs and documents `interrupted`; it does not guarantee exactly-once execution or continue work while offline. A durable queue remains outside v0.1.
- Deferred S04 review findings: [BL-001](BACKLOG.md#bl-001), [BL-002](BACKLOG.md#bl-002), [BL-003](BACKLOG.md#bl-003).
- Schema setup uses `create_all` for new tables, not migrations. Real OpenAI requests were not made; provider error mapping was tested without network access.
- S04 exposed results through HTTP; S05 adds the Streamlit view. CSV remains outside the completed S04 scope.

## S05 risks / limits
- Browser refresh resets Streamlit's selected vacancy; reselecting it loads the run history from backend with the latest run selected. Status updates are button-driven, without automatic polling. macOS Dark Mode appearance still needs owner verification because the local computer-use permission was denied during this check.
- Archiving retains the file, extracted text and historical evidence; only eligible unlinked documents can be permanently deleted. The local SQLite `BEGIN IMMEDIATE` lock serializes archive and run creation, but is not a multiworker locking design.
- CSV export and persistent HR reviewed flags/notes were not implemented. The backend has no review API; the UI does not imply that such notes are saved.
- Streamlit's local file-picker limit is 10 MB; if `MAX_UPLOAD_MB` is changed, both limits must be aligned. Backend validates file size independently.
- Resume deletion quarantines the stored file, commits the SQLite deletion, then purges the quarantined file. Storage failure before commit keeps the record; database failure restores the file. A rare purge failure after commit can leave an unreferenced private file in `UPLOAD_DIR/tmp`; it never removes analysis history or leaves a database reference to a missing file. This requires manual cleanup if observed.

## S06a risks / limits
- `FakeProvider` is a deterministic offline demo adapter for these exact synthetic phrases, not a general resume evaluator. No real-model accuracy or HR time saving has been measured.
- The seed refuses an existing vacancy with the same demo title. A network/API failure after vacancy creation can leave a partial demo vacancy; inspect it or use a new temporary SQLite. No automatic deletion is performed.
- PDF/DOCX bytes are stable across repeated generation in the checked environment; changes to document libraries may change binary hashes. The checked browser walkthrough was targeted, not a timed employer presentation.
