# S05 — повторная ручная приёмка

Проверять только на локальной временной SQLite, с `LLM_PROVIDER=fake` и синтетическими PDF/DOCX. Не использовать настоящие резюме. Открывать Streamlit и FastAPI только на `127.0.0.1`.

## Подготовка

1. Установить проект по `README.md`. Убедиться, что `python -m pytest -q` проходит.
2. Задать отдельные пути, например:

   ```bash
   export DATABASE_URL=sqlite:////private/tmp/ai-hr-s05-qa.sqlite3
   export UPLOAD_DIR=/private/tmp/ai-hr-s05-qa-uploads
   export LLM_PROVIDER=fake
   python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
   ```

3. Во втором терминале запустить `BACKEND_URL=http://127.0.0.1:8000 python -m streamlit run ui/app.py --server.address 127.0.0.1 --server.port 8501` и открыть `http://127.0.0.1:8501`.
4. Подготовить 15 **разных по имени** синтетических файлов вне репозитория: 11 текстовых PDF/DOCX с фразой о Python, SQL и Docker; один повреждённый PDF; один повреждённый DOCX; один PDF без текстового слоя; одну копию одного из корректных файлов с другим именем. В копии должны совпадать байты.

## Основной сценарий

1. На странице «Вакансии» создать тестовую вакансию. После создания выбранная вакансия должна открыться в режиме редактирования; одновременно форма создания не видна. Изменить описание и сохранить. Нажать «Новая вакансия»: новая форма должна быть пустой. Вернуться к выбранной вакансии без создания дубля.
2. На странице «Критерии» добавить `Python`, `SQL`, `Docker` как активные профессиональные критерии. После каждого добавления описание пустое, приоритет снова «Обязательный», флажок «Активен» включён. Изменить один существующий критерий и проверить, что количество критериев не увеличилось.
3. На странице «Резюме» отправить все 15 файлов одним запросом. В результатах ожидаются 11 `Готово`, 2 ошибки извлечения, 1 документ без текста и 1 дубликат. Ошибки отдельных файлов не должны прерывать пачку. Загрузчик после ответа пустой, таблица последней загрузки остаётся видимой. В списке хранится 14 записей, так как копия не создаёт новую запись.
4. Выбрать повреждённый PDF для удаления. До флажка подтверждения кнопка недоступна. После подтверждения удалить: документ исчезает из списка, остальные остаются. Это действие выполнять **до** анализа.
5. Повторно выбрать корректный файл через опустевший загрузчик и отправить. Должен появиться результат «Дубликат: Да»; нового Resume и нового POST при обычном обновлении Streamlit не возникает.
6. На странице «Анализ» нажать «Запустить анализ». Проверить выданный ID, статус и кнопку «Обновить». В этом наборе ожидаются 13 документов в запуске: 11 завершённых и 2 с ошибками; итог `completed_with_errors`. Открыть «Результаты», проверить находки по трём критериям, цитату и номер страницы PDF. Ошибочные документы остаются видимыми.
7. Вернуться в «Резюме» и попытаться удалить документ из завершённого запуска. Ожидается объяснение, что он связан с историей анализа; документ и результаты остаются. Запомнить ID запуска, обновить страницу браузера, раскрыть «Открыть предыдущий анализ» и открыть запуск по ID. Новый запуск не создаётся.

## Отдельный отрицательный сценарий: запрещённый критерий

Использовать **отдельную тестовую вакансию**, чтобы не оставить основной сценарий заблокированным.

1. Добавить активный критерий `Возраст кандидата` и один корректный синтетический PDF/DOCX с текстом. Можно добавить и разрешённый профессиональный критерий для сравнения.
2. Нажать «Запустить анализ». Должно появиться русское объяснение запрета анализа возраста и других чувствительных характеристик, предложение выключить/удалить критерий и список активных критериев. Запуск не создаётся.
3. Выключить критерий возраста на странице «Критерии» и сохранить. Статус должен отображаться как «Выключен».
4. Повторить запуск вручную. Он должен создаться. В snapshot запуска не должно быть выключенного критерия возраста; профессиональный критерий остаётся.

## Дополнительные отказы и результат

- Без активных критериев UI должен предложить открыть «Критерии» и добавить/включить критерий.
- Без готовых резюме UI должен предложить открыть «Резюме» и загрузить документ с текстом.
- При уже активном запуске UI должен предложить открыть его и обновить статус.
- При остановленном FastAPI UI показывает сообщение о недоступном сервере без внутренних деталей. Если upload завершился сетевой ошибкой, выбранные файлы остаются для повторной попытки.
- Зафиксировать фактические статусы, количество записей и замечания. S05 помечать COMPLETE/PASS только после повторной ручной приёмки владельца и архитектурного ревью.
